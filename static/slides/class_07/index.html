Good Practices in NetLogo

  • Start with a solid written specification (ODD)
    • Don’t go overboard
    • Develop specification iteratively with coding, testing, etc.
  • Bite-sized pieces:
    • Implement and test submodels separately
    • Independent implementation (spreadsheet, Python, R, Matlab, etc.)
  • Then build the complete model

Procedure Monitor Details

to go  ;  This is the master schedule

  ask turtles with [not finished?] [move]

  tick

  ;; At end of tick,
  ;; write procedure monitor output to file.
  PM-write-output
  ; stop when all the butterflies are at the summit, or
  ; 1000 ticks, whichever comes first
  if ticks >= 1000 or all? turtles [finished?]
  [
    stop
  ]
end ; of go

to move
  let rand random-float 1.0
  let old-patch patch-here

  PM-add (list who xcor ycor elevation q rand)
  PM-add [ (list pxcor pycor elevation) ] of
         max-one-of neighbors [elevation]
  let uphill? false
  ifelse random-float 1 < q
    [
      set uphill? true
      uphill elevation
    ] ; Move uphill
    [
      move-to one-of neighbors
    ] ; Otherwise move randomly
  PM-add (list uphill? (old-patch != patch-here)
               xcor ycor elevation)
  set visited? true
  if color-visited? [ set pcolor yellow ]
  PM-save-row
end ; of move procedure

Procedure Explorers

  • In a complete model, many things are happening
  • It can be hard to catch and identify infrequent anomalies or errors
  • Instead of running the whole model, write a procedure that tests a single procedure intensively
  • Open file flocking_PE.nlogox
  • Setup and run for a while
  • Stop and type “explore-headings” in the observer

Procedure Explorer Function

  • explore-headings procedure:
    • Picks a “test turtle” at random
    • Assigns two flockmates at random
      • One stationary flockmate
        • Positioned at 10,10
      • One moving flockmate

  • Stationary flockmate varies heading, but is always at 10,10
  • Moving flockmate goes to 0,0 and moves forward 10 in the direction it’s heading
  • Record:
    • Positions
    • Headings
    • Calculated:
      • Average heading of flockmates (stationary and moving)
      • Heading for target to fly to average position of flockmates

Graphical Analysis of Output

  • Actual average is calculated by NetLogo
    • If one is headed 354 and the other is headed 4, the average is 359
    • If one is headed 356 and the other is headed 6, the average is 1
  • The arithmetic average:
    • Case 1: 358 / 2 = 179
    • Case 2: 362 / 2 = 181

Defensive Programming

  • Unit tests:
    • Before you write a procedure or reporter, design tests to make sure it does what you intend
    • Execute tests during model runs
    • Consistency checks for agents:
      • Each turtle’s turtles-own variables should always be in a consistent state
      • Same for patches, links, etc.

Using TIF

  • Put the line

    __includes[ "tif.nls" ]

    near the top

  • Put the line

    initialize-tests

    in to setup

  • To start a group of tests:

    set-context "context description"

  • To report on the control center after performing a set of tests:

    resume-all-tests

  • For each test in the context:

    test-that "name of test"
expect-that <expression> <condition>

  • Example

    test-that "turtle is happy"
expect-that happy? is-true
test-that "hope is greater than fear"
expect-that hope is-greater-than fear

Using Unit Testing

  • Unit testing is valuable, but it can produce a lot of output to the command center
  • You may want to put the unit testing into test procedures rather than your main model code
  • Alternatively, have a global variable like testing? and only run the unit tests if testing? is true

Regression Testing

  • Find an error and fix it
    • As you continue to work on the model, make sure you don’t change something that brings the error back (regression)
  • Every time you find an error and fix it, write a test
  • Maintain a complete suite of tests to make sure that errors stay fixed
  • Regression tests should be run separately from running the model for research.
  • Run the complete suite of regression tests at every major milestone:
    • A new public release
    • Making a pull-request under revision control
    • Preparing to run an experiment with a new version of the model
    • …
